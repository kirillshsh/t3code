# Правила форка

Это форк `pingdotgg/t3code`, живущий у `kirillshsh/t3code`. Здесь правится дизайн мобильного
клиента под себя, поэтому расхождение с upstream — норма, а не проблема.

## Пуш

- Ремоут для наших изменений — `fork`. В `origin` (upstream) не пушить никогда.
- **Закончил работу — коммитим и пушим в `fork`.** Не «когда попросят», а в конце каждой задачи:
  `git push fork HEAD:refs/heads/<текущая-ветка>`. Сборка на сервере берёт код с GitHub, поэтому
  незапушенная правка для неё не существует.
- Из worktree пушить свою ветку тем же способом; временные `worktree-*` ветки на remote не выкладывать.

## Сборка APK

Просьбы вида «собери apk», «собери и установи», «проверю на телефоне» выполняются одной командой:

```bash
./apk.sh
```

Что она делает: пушит текущее состояние в `fork` (грязное дерево уезжает снимком в `wip/<ветка>`),
собирает release APK на сервере `sh`, скачивает его rsync-дельтой и ставит на подключённый телефон.

- `./apk.sh --no-install` — только собрать и скачать в `~/t3code-backup/t3code-latest.apk`.
- `./apk.sh --clean` — форсировать `expo prebuild`; нужен, если правился нативный конфиг
  (`app.config.ts`, `plugins/`, зависимости) и сборка этого не заметила.

Сервер сам решает, что пересобирать: `pnpm install` только при смене lockfile, `prebuild` только
при смене нативного конфига, остальное вытягивает инкремент gradle. Полный лог упавшей сборки —
`~/logs/build.log` на сервере.

Локальная сборка на маке (`build-android.sh`) осталась как запасной путь, но она заметно медленнее.
