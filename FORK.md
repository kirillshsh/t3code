# Правила форка

Это форк `pingdotgg/t3code`, живущий у `kirillshsh/t3code`. Здесь правится дизайн мобильного
клиента под себя, поэтому расхождение с upstream — норма, а не проблема.

## Пуш

- Ремоут для наших изменений — `fork`. В `origin` (upstream) не пушить никогда.
- **Закончил задачу — коммитим и пушим в `fork`.** Не «когда попросят», а в конце каждой задачи.
- В этом дереве часто работают несколько сессий сразу, поэтому ветка на форке может уйти вперёд.
  Тогда `git fetch fork && git rebase fork/<ветка>` и пуш заново — форсить чужие коммиты нельзя.
- Ветки вида `apk/*` создаёт скрипт сборки. Это срезы дерева, а не работа: их можно игнорировать
  и перезаписывать.

## Сборка APK

Просьбы вида «собери apk», «собери и установи», «проверю на телефоне» выполняются одной командой:

```bash
./apk.sh
```

Она снимает срез рабочего дерева (вместе с незакоммиченным), кладёт его в `fork/apk/<ветка>`,
собирает release APK на сервере `sh`, привозит его rsync-дельтой и ставит на подключённый телефон.

- `./apk.sh --no-install` — только собрать и скачать в `~/t3code-backup/t3code-latest.apk`.
- `./apk.sh --clean` — форсировать `expo prebuild`; нужен, если правился нативный конфиг
  (`app.config.ts`, `plugins/`, зависимости) и сборка этого не заметила.

Дорогие шаги сервер пропускает сам: `pnpm install` только при смене lockfile, `prebuild` только при
смене нативного конфига, остальное добирает инкремент gradle. Сборка живёт на сервере отдельным
процессом, так что оборванный ssh её не убивает — скрипт переподключается к логу. Полный лог
упавшей сборки лежит на сервере в `~/logs/build.log`.

Локальная сборка на маке (`build-android.sh`) осталась запасным путём и заметно медленнее.
